# design-refactor · 布局重构稿（A–D 对照 + E 采用）

打开 `index.html` 看对照，点「采用」那张卡进入 `e-unified.html`（可点击的原型）。

所有页面都是单文件静态稿：共用 `assets/base.css` 的令牌与控件，没有任何请求，
按钮不假装写成功。深浅色跟随系统，也可以在地址后加 `?theme=dark`。

## 采用的形态：E

骨架取自 **C**（左队列 + 右详情），导航取自 **D 的 dock**，信息架构按需求砍到最小。

| 层级 | 有什么 | 在哪 |
| --- | --- | --- |
| 项目上下文 | acme/widgets、other/lib、全部项目 | 左上角下拉 |
| 项目级导航 | Issue、设置、技能 | 底部 dock（三项） |
| 全局入口 | 系统状态、运行时开关、连接、只读常量 | dock 最右「系统」→ 模态框 |
| 顶部状态带 | 待处理 / 运行中 / 失败 / p95 | 一行只读数字 |

### 砍掉的页面与它们的去向

| 原页面 | 现状 |
| --- | --- |
| 总览 | 删除。它回答的「现在什么状态」压进顶部状态带（4 个数字 + 1 个降级 chip） |
| 系统 | 删除。doctor 五项检查、运行时开关、连接、只读常量都进「系统」模态框第一屏 |
| 成本 | 删除。金额只作为单任务的元信息出现在运行详情里，不再有独立页 |
| 质量（被改回） | 删除。被改回的事件走审计，审计本身也不再单独成页 |
| 审计 | 删除。写回动作的审计 ID 落在详情「为什么停在这里」的最后一行 |

如果后面发现「被删掉的东西还是有人天天看」，**先往状态带加数字，再考虑加页面**——
这条顺序比反过来便宜得多。

### 三个视图各自的职责

- **Issue（默认）**：左 340px 队列（按 阻塞 / 等人 / 正在跑 分组）+ 右详情。
  详情只有三块：为什么停在这里（结论/建议/影响/上次动作）、证据（stderr 或分类理由）、
  会话摘要（最近 3 条）。动作按钮就在标题下面一行，不用滚。
- **设置**：左分区（通用 / 事件绑定 / 标签 / 执行）+ 右表单，表单宽度锁在 700px。
  所有文案都标明「这个开关的代价是什么」，例如容器内存那行直接写「2G 时 vite build 会 OOM」。
- **技能**：左列表 + 右定义预览（也是主从）。预览只讲「这个技能怎么判断」「什么不许让渡」，
  不讲实现——实现是 worker 的事。

### 能点的地方

- 左上角：切项目（列表与计数实时跟着变）、点空白或 `Esc` 收起
- dock：Issue / 设置 / 技能切换；最右齿轮开「系统与全局设置」模态框（`Esc` 或点遮罩关闭）
- 队列：点行选中、`j` / `k` 上下移动、`Enter` 回到详情顶部；三个 tab 分别看待处理 / 运行中 / 已完成
- 设置：分区切换、开关、下拉、文本域都能动（只改本地状态）
- 技能：点行切预览

```
design-refactor/
  index.html          ← 入口：E 的卡片 + A–D 四张缩略图 + 选型对照表
  e-unified.html      ← 采用方向的可点击原型
  a-console.html      ← 对照：经典侧栏（密度优先）
  b-topbar.html       ← 对照：顶部主轴 + 宽单列（阅读优先）
  c-inbox.html        ← 对照：主从双栏 / 收件箱（处理优先，E 的骨架来源）
  d-bento.html        ← 对照：Bento 网格（全局优先，dock 的来源）
  assets/base.css     ← 共用令牌与控件（按钮、chip、表格、spark）
  assets/theme.js     ← ?theme=dark|light 覆盖系统偏好
```

E 的内部分层：`<style>` 里按 ①外壳 ②dock ③视图容器 ④Issue ⑤设置 ⑥技能 ⑦模态框 ⑧窄屏 分段；
两个 `<script>`：第一个是纯数据（`ISSUES` / `SKILLS` / `GROUPS` / `SET_META`），
第二个是行为（`state` + `renderX()` + 事件绑定）。改文案只碰第一个，改交互只碰第二个。

## 边界与未做的事

- 没接 `GET /api/*`：字段名对齐 `packages/contract`（`successRate` / `p95Ms` / `failureClass` /
  `outcome` / `delivery`），但数字是手写的快照。
- 没动 `apps/panel` 的代码。这一轮只产出稿子；真正落地要按 `AGENTS.md` §5 的验证矩阵走
  （面板改动必须跑 `pnpm --filter @pi-issue-bot/panel test` + `typecheck`，不能只跑 `test:all`）。
- **没做浏览器渲染验证**：`agent-browser open` 在本机两次 90s 无响应，仓库里也没有 jsdom。
  已做的静态检查：两段脚本 `node --check` 通过；`<div>` 开合 223/223、`<section>` 3/3；
  脚本引用的 19 个 id 全部存在。视觉与交互仍需人眼过一遍。

## 接进 panel 的落地顺序（如果这个方向被采纳）

1. **先搬骨架，不改内容**：`AppLayout` 换成 状态带 + `main.stage`，把现有五个全局页先塞进
   dock 后面的隐藏分支，确认没有路由回归（`routes/__tests__` 全绿）。
2. **再砍页面**：删 `overview` / `costs` / `quality` / `audit` / `system` 五条路由，
   把 `overview` 的四个数字搬进顶栏（`useOverview` 的查询保留，只是展示位置变了）。
   这一步会动契约外的 UI 测试，要按页删。
3. **最后做主从**：`issues` 与 `issue-detail` 合并成一个视图（选中项进 URL，保证深链接），
   详情只保留「结论 / 证据 / 会话」三块，其余块按需折叠。这一步风险最大，建议单独一个 PR。
4. 每步都要能给「被删掉的东西去哪了」一个明确答案，否则就是悄悄丢功能。

## 第二轮改动（当前状态）

1. **左栏统一**：Issue 队列 / 设置分区 / 技能列表都 320 宽，共用 `.rail-head`（30px，小标 + 计数）、
   行高 28、「左侧 3px accent 条 + accent-soft 底」的选中态。
2. **Issue 页改成会话流**（不再是分区卡片）：常驻标题行（`⋯` 里放重跑 / 标记人工 / 在 GitHub 打开）
   → 折叠的原文卡（默认只露标题）→ 居中可折叠的**系统提示词**（四层 + token 数）
   → 右侧 **human 气泡**（触发 chip + 等宽事件行）→ 左侧 **agent**（无卡片、三层工具、
   `verdict`/`actions` 默认收起、model/token chips）→ 居中**平台写回行**（✓ / ✕）→ 底部输入区。
   「证据」「为什么停在这里」两块已删除。
3. **「系统」模态框新增两块**：供应商（名称 / base URL / key 掩码 / 连通性 / model）与
   模型角色（`agent` / `format` / `classify` / 兜底 + 输入输出单价）；另有「GitHub 身份」
   （默认 bot，可填个人 PAT，未填就用 bot）。
4. **发送框只出 UI**：按钮 `disabled`，`title` 写明缺 `POST /api/issues/:owner/:name/:number/messages`；
   本期不做发送。
