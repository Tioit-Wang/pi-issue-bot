## 五、跳过项与残余风险

1. **C3 / C4 的「面板显示」没做**（不是没做数据）：`apps/panel/**` 不在本包可写面。字段与读路径已就绪，面板 owner 只需两处小改：
   - 队列 / 状态带计数：`apps/panel/src/lib/issue-counts.ts`（或 `routes/issues.tsx:315-328`）改用 `page.totalEstimate`；
   - agent 轮折叠块：`components/issues/IssueConversation.tsx` 的 `AgentRow` 加「默认收起的 verdict / actions」。
2. **信封 JSON 原样透传的体积**：`IssueTurn.actions` 是 `envelopes.actions` 原文，v2.1 单条评论正文上限 60 000 字（`packages/envelope/src/v21.ts:210`），20 条动作理论上一轮可达 ~1 MB。没有截断，为的是「折叠显示的就是模型真的交了这份」；如果长期出现超大信封，应在面板侧折叠 + 按需拉 `/trace`，而不是在契约里砍掉字段。
3. **`totalEstimate` 的代价**：每次 `/api/issues` 多一次同 CTE 的 `count(*)`（`issues.ts:602-609`）。`agg` 里有 6 条 lateral，数据量上去后这条统计会变贵；到那时再考虑物化计数或按状态分桶的缓存列（现在加就是第二处口径）。
4. **`.optional()` 的偏离**（见 §二.1）：等面板夹具补齐后应收紧为 `.nullable()`，否则契约对「服务端一定会给这些键」这件事只是口头约定。
5. **主贴正文为空的措辞**：`body: ""` → `null`，面板会显示它自己的「契约没有提供 issue 主贴正文」文案（`IssueConversation.tsx:237-241`）。字段现在是真的有了，所以那句文案在「用户确实没写正文」时会误报成「契约缺失」——应改由面板区分，本包不改 `apps/panel`。
