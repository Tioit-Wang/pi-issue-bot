# P0-3 幂等归一化越界（内容级去重口径收窄）

- 缺陷：`normalizeForIdempotency` 做了远超需求口径的归一化，导致「只改标点」「只挪代码块」被判成同一内容，新问题被静默吞掉（`docs/requirements.html` §5：去首尾空白、合并连续空行；不做语义近似判断）。
- 改动面：`apps/server/src/agent/canonical-text.ts` 的 `normalizeForIdempotency` 与其专用常量；两个断言了旧行为的测试。
- 未动：`stripAliases` / `stripAliasMentions` / `aliasPatternsOf` / `escapeRegExp`、`fingerprint.ts`、需求文档。

## 1. 规范化步骤对照

| 步骤 | 改前 | 改后 |
|---|---|---|
| 空正文短路 | `text === '' → ''` | 去掉（`''` 经 trim 仍为 `''`） |
| 代码区 | `maskCodeRegions(text)` 抹成等长空白 | **不做**，代码区原样参与 hash |
| `@handle` | `AT_HANDLE` 替换成空格 | **不做** |
| 标点/符号 | `PUNCTUATION_OR_SYMBOL`（`\p{P}\p{S}`）替换成空格 | **不做** |
| 空白 | `WHITESPACE = /\s+/gu` 全部压成一个空格（换行被压平） | **不做**行内压平 |
| 连续空行 | 不存在（被上一步整体压掉） | `CONSECUTIVE_BLANK_LINES = /\r?\n(?:[ \t]*\r?\n){2,}/gu` → `\n\n` |
| 首尾空白 | 末尾 `trim()` | 末尾 `trim()`（保留） |

实现后：`normalizeForIdempotency(text) = text.replace(CONSECUTIVE_BLANK_LINES, '\n\n').trim()`。

正则只吃「空行之间」的空白，`[ \t]*` 必须紧跟换行，因此不会吃掉下一行正文的缩进（缩进列表 / 代码块不受影响）。

因此被删除的常量：`AT_HANDLE`、`PUNCTUATION_OR_SYMBOL`、`WHITESPACE`，以及不再需要的 `maskCodeRegions` import（lint 无 unused 报错）。

## 2. 受影响的测试用例（改了哪些、为什么）

`apps/server/test/agent-message.test.ts`

| 用例 | 处理 | 原因 |
|---|---|---|
| `去 @ / 压空白 / 去标点后等价`（原 L-02） | **删除并替换** | 直接断言旧越界行为（`'@bot 打个标签'`、`'@bot  打个标签！'`、`'@bot\n\n 打个标签。 '` 全等于 `'打个标签'`）。需求口径下这三条必须互不相等，断言本身就是缺陷。 |
| 新增 `只做两件事：去首尾空白 + 合并连续空行` | 新增 | 钉住新口径的正例：首尾空白、`\n\n\n\n` → `\n\n`、单个空行不动、空串。 |
| 新增 `不压行内空白、不把多行压成一行` | 新增 | 钉住「合并空行 ≠ 把多行压成单行」这条最容易回退的边界。 |
| 新增 `不摘 @ 提及、不去标点、不抹代码区` | 新增 | 钉住三步被删掉的归一化确实不再发生。 |
| `代码区不参与归一化（围栏块整体被蒙掉）` | **删除并替换** | 断言 `'看这里\n```\nconst a = 1;\n```\n然后再说'` → `'看这里 然后再说'`，正是需求禁止的「只改代码块算同一内容」。 |
| 新增 `只改标点 / 只挪代码块 → 不同内容` | 新增 | 反例侧覆盖：这两类改动必须产生不同内容（`'const a = 1;'` vs `'const a = 2;'`）。 |
| `不转小写` | 保留 | 与需求一致（OQ-10 未采纳）。 |
| `L-02：归一化等价的两句话 fingerprint 相同` | **改数据** | 原数据 `'@bot 打个标签'` vs `'@bot  打个标签！'` 依赖去别名 + 压空白 + 去标点；改为只差首尾空白 / 空行（`'  打个标签\n\n\n'`），这才是需求认的「同一内容」。 |
| 新增 `L-02：只改标点 → 不同 fingerprint` | 新增 | 反例侧覆盖 fingerprint 层。 |
| `同一句话（含不同别名/空白）→ 同一 fingerprint` | **改数据 + 拆成两条** | `composeAgentMessage` 先做 `stripAliasMentions`（别名是噪声这层保留），原数据第二句多一个 `！`，收窄后必然不同键。改为「不同别名 + 首尾/空行差异 → 同键」，并新增「只改标点 → 不同键」。 |

## 4. 风险：口径收窄带来的重复处理（可接受）

1. **别名写法不再被抹平**：hash 里保留了正文原文，别名也不例外。`composeAgentMessage`（mention 路径）先做 `stripAliasMentions`，所以 `@pi-bot 打个标签` 与 `@issuebot 打个标签` 仍是同一个键；`v21MessageFingerprint`（评论路径）直接用原文，因此同一个人换个别名再 @ 一次会是新一轮任务。需求明确「宁可多处理一次」，接受。
2. **只改标点 / 空白 / 代码块 → 重跑**：这正是需求要的行为；代价是多烧一次 token。
3. **行内多空格 / 单换行 vs 双换行 → 不同内容**：粘贴时被编辑器重排过空行的同一段话可能重跑一次。
4. **潜在重复累积**：`agent_messages` 的永久幂等键变多，历史数据的旧键不会因收窄而失效（旧行仍在），只是新内容不再撞旧键；无数据迁移需求。
5. **遗留（未在本轮改动）**：`apps/server/src/agent/message.ts` 里 `text: withoutAlias` 上方的注释「行内空白不动（归一化会压）」已过时；按约束未改该文件，建议后续顺手修正措辞。
