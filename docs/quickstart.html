pi-issue-bot README / 快速开始
10 分钟 · 单机
QUICKSTART

快速开始

在本机跑起来，接一个仓库，看它处理第一个 issue。

前置
Node 24 · pnpm 10 · PG 16 · Docker
默认端口
3000 / 面板 5173 / metrics 9464
默认写入
dry-run 开启（不写 GitHub）
难度
一条命令一步

1装依赖并确认基线

三条门禁全绿再往下走；任一红说明环境不对，先修环境。

pnpm install
pnpm -r typecheck
pnpm -r test
pnpm lint
注意

有 25 个服务端测试硬依赖真 PostgreSQL，没有库时 pnpm -r test 会失败。要么先做第 2 步再回来跑，要么把这批的失败当作预期。

2建库并跑迁移

一个 PostgreSQL 同时存业务表和队列（pg-boss），不需要 Redis。DSN 从环境变量读，没有 --dsn 参数。

$env:PI_BOT_PG_DSN = 'postgres://postgres:postgres@127.0.0.1:5432/pi_issue_bot'
pnpm cli -- migrate

迁移结束应看到 16 张初始表与 schema_migrations 账本；重复执行是幂等的。

3写最小环境变量

先只填四项：数据库、webhook 密钥、模型端点、数据目录。其余留空即可启动。

$env:PI_BOT_PG_DSN          = 'postgres://postgres:postgres@127.0.0.1:5432/pi_issue_bot'
$env:PI_BOT_WEBHOOK_SECRET  = 'local-dev-secret'
$env:PI_BOT_MODEL_BASE_URL  = 'https://api.deepseek.com/v1'
$env:PI_BOT_MODEL_NAME      = 'deepseek-chat'
$env:PI_BOT_MODEL_API_KEY   = 'sk-...'
$env:PI_BOT_DATA_DIR        = 'C:\pi-bot-data'

模型端点只要说 OpenAI 兼容协议就能用（DeepSeek、OpenAI、MiMo 都一样）；配了 key 却没配模型名，启动会直接报错。

4起服务

pnpm cli -- serve

起来后有三个地址：http://127.0.0.1:3000/healthz、/api/* 与面板用的静态资源、http://127.0.0.1:9464/metrics。缺表会直接抛 MIGRATIONS_PENDING，回第 2 步。

另开一个终端做环境预检，13 项里只要没有 fail 就能继续：

pnpm cli -- doctor

5打开面板

开发态面板跑在 5173，/api 自动代理到 3000。没接 GitHub 也能先看界面：加 ?mock=empty 用假数据。

pnpm --filter @pi-issue-bot/panel dev
# http://127.0.0.1:5173/?mock=empty

四个状态可以直接看：?mock=empty、?mock=error、?mock=unauthorized、?mock=slow。

6接 GitHub 并投一次事件

  1. 建 GitHub App，权限给 Issues（读写）与 Pull requests（读写），订阅 issues、issue_comment、pull_request。
  2. 把 App 装到目标仓库，填三个变量：PI_BOT_GITHUB_APP_ID、PI_BOT_GITHUB_APP_PRIVATE_KEY_PATH、PI_BOT_GITHUB_INSTALLATION_ID，重启服务。
  3. Webhook 指向 https://<你的域名>/webhook，secret 与 PI_BOT_WEBHOOK_SECRET 一致。本机调试用 ngrok 之类的隧道。
  4. 在那个仓库开一个 issue（或评论 @pi-bot /issue-triage）。
  5. 面板进 /repos/<owner>__<name>/issues，能看到这次会话：触发了什么、模型说了什么、写了什么。
安全

PI_BOT_DRY_RUN 默认 true：这一次不会真的评论、打标或建 issue，只落一条 writeback.dry-run 事件。确认行为符合预期后，再设为 false。
