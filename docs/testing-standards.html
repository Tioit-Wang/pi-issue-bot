TESTING STANDARDS

测试规范

标准只有一句：改动之后，你能指出哪一条断言会红。

1命令

pnpm -r typecheck                          # 逐包 tsc --noEmit
pnpm -r test                               # 逐包 vitest run（25 个文件需要真 PG）
pnpm --filter @pi-issue-bot/panel test     # 面板（jsdom + MSW）
pnpm lint                                  # 含依赖方向门禁
命令注意
pnpm test:all根配置只匹配 *.test.ts，环境是 node。面板 21 个测试文件里有 17 个是 .tsx，不会被跑到。
pnpm -r testopenTestDb() 不 skip：没有 PostgreSQL 时那 25 个文件直接失败，不算「全部通过」。
真 Docker / 真 git用 skipIf 按机器能力跳过，文件头写明条件，交付里点名。
CI仓库没有 CI，也没有覆盖率门禁；门禁就是上面四条在本机跑绿。

DSN 变量目前三个名字并存：PI_BOT_TEST_DSN（helpers/queries-db.ts）、PI_BOT_TEST_DATABASE_URL、PI_BOT_DATABASE_URL。按被测文件用对应变量。

2分层与位置

层范围放哪里典型对象
U纯函数apps/server/test/*.test.ts、packages/*/test/decideEvent、planLabelDelta、decideRetry、renderPrompt、buildHostConfig
I真 PG + 假 GitHub / 假 RACPapps/server/test/（helpers/）queries/*、webhook 九步、runTask、jobs/*、dispatcher
Pjsdom + MSWapps/panel/src/**/__tests__/、apps/panel/test/路由四态、导航、设置草稿、技能模态框、format
M真环境手验，不计入自动化结论写进交付说明@ 是否点到人、GitHub 是否拒写、模型结论像不像人话
  • 服务端测试与被测代码分离，命名 <模块>-<子主题>.test.ts（queue-retry-policy、queries-costs-audit、no-merge）。
  • 夹具不叫 *.test.ts，放 helpers/；test/git-fixture.test.ts 是历史遗留。
  • describe / it 用中文；文件头写测什么、为什么这样假。
  • 根 vitest.config.ts 只放共享默认值，各包 mergeConfig 继承并覆盖 include。

3四段骨架

3.1 纯函数（U）

import { describe, expect, it } from 'vitest';
import { decideRetry } from '../src/queue/retry-policy.ts';

describe('重试矩阵', () => {
  it('超时不重试', () => {
    expect(decideRetry([signal('timeout')])).toEqual({ action: 'none' });
  });
  it('429 用 startAfter，不用 retryLimit', () => {
    expect(decideRetry([signal('rate-limit')], { attempts: 2, retryAfterMs: 30_000 }))
      .toMatchObject({ action: 'start-after', delayMs: 30_000 });
  });
});

显式导入 vitest（globals: false）；相对导入带 .ts；断言传进去的参数，不只断言返回值。

3.2 真库集成（I）

import { afterAll, beforeAll, beforeEach, describe, expect, it } from 'vitest';
import { openTestDb, seedStandard, type TestDb } from './helpers/queries-db.ts';
import { costsResponseSchema } from '@pi-issue-bot/contract';

describe('queries/costs（真库）', () => {
  let db: TestDb;
  beforeAll(async () => { db = await openTestDb(); });
  afterAll(async () => { await db.truncate(); await db.close(); });
  beforeEach(async () => { await db.truncate(); await seedStandard(db); });

  it('按仓库拆分与手算一致', async () => {
    const r = await db.queries.costs({ window: '7d' });
    expect(() => costsResponseSchema.parse(r)).not.toThrow();
    expect(r.byRepo[0].costUsd).toBeCloseTo(0.22, 6);
  });
});

隔离靠文件级 pg_advisory_lock + fileParallelism: false；truncate 只清自己写过的表；时钟用 FIXED_NOW 注入；响应必须过契约 parse()。

3.3 扫源码的不变量

it('src 里没有任何合并调用', () => {
  const files = walk(['apps/server/src', 'packages/contract/src']);
  expect(files.length).toBeGreaterThan(50);   // 先证明扫到了文件，防空转
  for (const f of files) {
    const text = read(f);
    for (const re of [/\\.merge\\(/, /mergePullRequest/, /merge_pull_request/]) {
      expect(text).not.toMatch(re);
    }
  }
});

3.4 面板组件（P）

const server = setupServer(...createHandlers());
beforeAll(() => {
  server.listen({ onUnhandledFrame: 'error' });   // msw 3 的选项名
  server.events.on('request:start', (e) => requests.push(e.request.url));
});
afterEach(() => server.resetHandlers());

it('内容态并带时间窗参数', async () => {
  renderWithProviders(<CostsPage />, { route: '/costs?window=7d' });
  expect(await screen.findByTestId('costs-content')).toBeTruthy();
  expect(requests.some((u) => u.includes('/api/costs') && u.includes('window=7d'))).toBe(true);
});

四态靠 URL 上的 ?mock=empty|error|unauthorized|slow 制造，不塞组件 prop；断言用 {testId}-loading|-error|-empty|-content|-offline。

4必须写 / 可跳过

变更层级最低验收
修 bugU/I先有会红的用例（或明确基线），再修，再绿
新功能U+I分支用例 + 一条从真实入口进的用户路径
重构沿用声明保住的不变式，跑现有测试证明
契约变更契约生产方与消费方都覆盖，gen:openapi 产物同批提交
迁移I真库跑通，不假设空库
队列 / 重试 / 并发U+I信号优先级、重试决策、并发闸各有断言
安全边界U/扫描拒绝路径优先测，扫描型不许放宽
面板交互P四态 + 键盘、脏状态拦截、错误重试
文档 / 注释 / 样式—核对路径、命令、数字；不要求单测

可跳过但必须给替代验证：纯文档或注释；不影响交互与可访问性的视觉调整；机械生成的产物；已被现有测试覆盖的无分支重构。

  • C8skip 已点名，未混进「全部通过」

6常见坑

症状原因怎么办
面板测试「全绿」但没测到改动用了 test:all，根 include 不含 .test.tsx改用 --filter @pi-issue-bot/panel test
随机红、重跑就好共用真库没隔离，或依赖执行顺序advisory lock + fileParallelism: false + 只清自己的表
连不上库三个 DSN 变量名并存按被测文件用对应变量
改过 process.env 后全错没有复原，且 repo-config 有模块级缓存finally 复原 + resetDefaultRepoSettingsCache()
扫描型测试永远绿路径写错，扫到 0 个文件先断言 files.length > N
夹具被当成用例跑夹具命名成 *.test.ts放 helpers/，不叫 *.test.ts
ResizeObserver is not definedjsdom 缺它，Recharts 要test/setup.ts 已补，别绕过 setup
等待用 sleep，机器慢就红没有同步点waitFor(predicate) / findBy*
只断言 outcome === 'succeeded'只证明跑完，不证明做了什么断言评论条数、标签集合、落库行数
