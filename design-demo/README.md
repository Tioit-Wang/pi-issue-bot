# pi-issue-bot 控制台 · 设计 Demo（固定流水线版）

10 个静态页面，双击 `design-demo/index.html` 即可打开（单文件、无依赖、无构建环境要求）。
所有页面共享同一套外壳与视觉令牌；**数据全部是演示数据**，顶栏有明确标注。

这一版按 `docs/plan-fixed-pipeline.md` v1.5 重做：每个 issue 固定走
**阶段 0 格式检查 → 阶段 1 标签分类 → 阶段 2 Agent**，**每一步都是一个独立的 agent 对话**。

## 打开方式

直接打开 `design-demo/index.html`。页面之间用左栏、面包屑、行内链接互相跳转，
不需要起本地服务。

想看深色模式：在地址后加 `?theme=dark`（或点右上角切换，会记住）。

## 页面与路由

| 文件 | 页面 | 对应路由 |
| --- | --- | --- |
| `index.html` | 工作台（今天需要人做什么） | `/` |
| `pipeline.html` | 流水线看板 + 门禁处置 + 系统常量 | `/repos/:repo/pipeline` |
| `issues.html` | Issue 中心（三阶段列表 + 三步骤详情） | `/repos/:repo/issues` |
| `run.html` | 阶段会话（某一步的完整 agent 对话） | `/repos/:repo/issues/:n/stages/:stage` |
| `costs.html` | 成本 | `/costs` |
| `quality.html` | 质量（被改回） | `/quality` |
| `audit.html` | 审计 | `/audit` |
| `skills.html` | 技能 | `/skills` |
| `system.html` | 系统、doctor、确定性作业 | `/system` |
| `settings.html` | 仓库设置（5 分区） | `/repos/:repo/settings/:section` |

## 三个步骤怎么被表达出来

**列表里**：每行一条三段进度条 + 当前阶段名 + 类别 + 状态 + 停留时长；
阶段 0 显示「失败 2 / 5」，阶段 1 / 2 显示「重跑 2 次」（重跑不限次数），`ready` 后被改过正文就显示「结论陈旧」。

**详情里**：竖排三张步骤卡，每张卡自带会话类型与生命周期：

| 步骤 | 会话 | 卡片上的元信息 |
| --- | --- | --- |
| 阶段 0 格式检查 | 一次性 `create → run → archive` | `2 轮 · 11s · 已归档` |
| 阶段 1 标签分类 | 一次性，必须给 `path:line` 证据 | `4 轮 · 42s · 已归档`，并显示 `@managers（defect 首次）` |
| 阶段 2 Agent | 按 issue 复用，30 轮 / 7 天轮换 | `7 轮 · cursor 12 · 3 天前建立` |

`not-found`（虚拟缺陷 / 无法分类）是个例外：它**停在阶段 1 等管理员**，
只有 managers 的评论会触发重分类，`info_requested_at` 为空、**不计入 48 小时关闭**。
Demo 里 `#308` 就是这种形态（列表上标「等管理员」，不是「待人补充」）。

**会话页**（`run.html`）把这个区别做实：左边是真正的多轮对话（AI 评论、作者补充、
`/recheck`、写回动作），右边固定「会话状态 / 阶段结果 / 进入条件 / 门禁」。
页签里还能看到**提示词层序与预算**（head → P1 → AGENTS.md → 技能 → tail，
`available = min(4000, 12000 − …)`），以及信封顶层带 `stage` 字段。

## 可点击的地方

- 左栏导航、面包屑、所有行内链接
- `⌘K` / `Ctrl+K` / `/`：命令面板，可搜页面与仓库，↑↓ 选择、Enter 进入
- 左栏顶部仓库切换器：切换上下文，issue 列表随之过滤（选择会记住）
- 工作台：刷新、待办行（自动关闭最靠前）、跳看板 / 设置
- 流水线：四列看板（卡片进 issue 详情）、门禁处置表、系统常量
- Issue 中心：搜索、阶段下拉、状态 chip（计数按仓库实时算）、点行切换详情、
  `j` / `k` 移动、`Enter` 打开当前会话；详情里 `/recheck`、`/pipeline next|prev` 有原因提示
- 阶段会话：四个页签、复制会话 ID、「仅错误」过滤、展开信封 JSON
- 成本：7 / 14 / 30 天切换（图表、指标、按仓库表一起联动）
- 质量：按命令 / 按仓库切换、点行展开改回详情
- 审计：搜索、动作筛选、点行展开审计 JSON、导出 CSV
- 技能：启停开关、打开「定义」抽屉（`issue-pipeline` / `/deep-review`）、dry-run
- 系统：重新体检（逐项跑，保留 1 项降级）、暂停全部（确认框 → 横幅 → 恢复）
- 设置：五个分区切换（支持 `#prompt` 这类深链）、改字段出现保存条、提示词预览抽屉、
  四条版本线的「系统默认 / 项目版本」切换
- 右上角明暗主题切换

## 配置面收成了五块

v1.5 把可配的东西压到最少，设置页就按这个形状做：

1. **管理人员**：`requirement` / `defect` 各自 @ 谁；`not_found` / `other` 不 @。
   有一个用户名解析不到 → 该类别降级为只回评论并记审计。
2. **标签词表**：两张表。阶段标记（`pipeline:format/classify/agent/done`）由流水线写；
   `role → 仓库标签` 由分类结论写（`requirement→enhancement`、`defect→bug`、`other→question`）。
3. **提示词**：四条版本线 `project / format_check / classify / agent`，
   每条可切「系统默认 / 项目版本」，带字符数与层序预算。
4. **系统常量**：格式累计 5 次不通过自动关（`PIPELINE_FORMAT_MAX_FAILS`）、
   `format/awaiting_info` 满 48 小时关闭、运行失败连续 2 次 → blocked、
   30 轮 / 7 天轮换、4000 字符、120s 冷却——全部只读。
   配置里刻意没有 `close_after_hours`、`max_runs_per_stage`，也没有「重跑上限」。
5. **运行时**：只留 `@` 提及开关、dry-run、去重窗口；写回闸门是固定行为。

## 视觉令牌

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底 | `oklch(0.988 0.002 95)` | `oklch(0.168 0.008 264)` |
| 面 | `oklch(1 0 0)` | `oklch(0.207 0.009 264)` |
| 主文字 | `oklch(0.205 0.012 264)` | `oklch(0.955 0.004 264)` |
| 选区 / 焦线 | `oklch(0.475 0.088 205)` | `oklch(0.79 0.098 195)` |
| 成功 / 警示 / 失败 | `155` / `72` / `27` 色相 | 同色相提亮 |

- 行密度：表格 33px、issue 行 54px（两行）、控件 29–30px；间距走 4px 网格。
- 层级只用 1px hairline 与留白；阴影只给浮层（命令面板、抽屉、对话框、toast）。
- 数字统一 `tabular-nums`；ID / 命令 / 路径统一等宽。
- 状态不靠颜色单独表达：状态点、徽章文字、`title` 里的事实三选二。

## 文件结构

```
design-demo/
  index.html … settings.html   ← 产物：10 个单文件页面（CSS/JS 已内联）
  _src/
    app.css                     ← 令牌、外壳、组件、图表、流水线组件
    app.js                      ← 外壳交互 + 各页面逻辑 + 演示数据 + 图表绘制
    build.mjs                   ← 把片段包进外壳并内联，输出到上一级
    pages/*.html                ← 页面正文片段（含 title / page / nav / crumb 头注释）
```

改完 `_src` 后重新生成：

```bash
node design-demo/_src/build.mjs
```

## 边界

- 只有前端，没有接 `GET /api/*`；所有数字来自页面里的演示数据。
- 会话页（`run.html`）固定演示 **#318 的阶段 2**；从其它 issue 点「打开会话」也落到这一页，
  用来展示版面与信息结构，不代表数据联动。
- 没有实现写接口的动作（重跑、保存配置、暂停、代发评论）都走「解释原因」的 toast，
  不假装成功——评论尤其明确：面板不代发，回复会作为下一轮进入会话。
- 响应式做了 1280 / 1080 / 860 三档断点；窄屏下左栏变抽屉，双列变单列。
